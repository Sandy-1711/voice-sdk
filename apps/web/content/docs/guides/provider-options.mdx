---
title: Provider options
description: The escape hatch — reaching the underlying API for anything core does not model.
---

Core models what providers have in common. `providerOptions` reaches everything
else, so a missing field is never a reason to drop out of the SDK.

```ts
await voice.speak({
  text: "Hello.",
  format: { container: "raw", sampleRate: 24000 },
  providerOptions: { mip_opt_out: true },
});
```

The object is merged into the request body the provider mapped, with the keys
that API actually uses. It is available on `speak`, `speakStream`, `transcribe`,
`openTTSSession` and `openSTTSession`.

## Merging is one level deep

Nested plain objects merge rather than replace, so setting one field does not
silently drop the siblings the SDK mapped for you. Scalars, arrays and class
instances replace outright.

```ts
// The mapper produced { voice: { id, mode, experimental_controls: { speed } } }.
providerOptions: { voice: { experimental_controls: { emotion: ["curiosity"] } } }
// speed survives. mode and id survive.
```

## What it cannot override

**Anything the SDK reports back.** The audio format above all: a `SpeakResult`
carries the format the bytes are actually in, and letting `providerOptions`
change what went on the wire while the reported value stayed put would make that
a lie. Mapped format fields are applied _after_ the merge and win.

Everything a caller cannot observe from the result is fair game.

## The cost

`providerOptions` is provider-specific by definition. Code that uses it stops
being portable across providers, which is the thing the rest of this SDK exists
to give you. Reach for it when you need to; treat a reach as a signal that core
might be missing something worth modelling.
